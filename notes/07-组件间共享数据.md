# 组件间共享数据:把 state 提升到公共父组件

> 📌 本文的 React 技术知识,来自 D 盘的 **DeepSeekMonitorWindows-1** 项目。

这是 React 官方文档快速入门(zh-hans.react.dev/learn)「组件间共享数据」一节,紧接 05 篇的结尾:每个 `<MyButton/>` 都有自己独立的 `count`,点哪个只有哪个变。可如果**两个组件要显示同一份数据**,就不能各存一份了——官方给出的答案是**状态提升(lifting state up)**。

## 官方图示:每个按钮的 count 是私有的

起初,每个 `MyButton` 的 `count` state 均为 0:

```
MyApp
 ├── MyButton   count = 0
 └── MyButton   count = 0
```

点击第一个 `MyButton`,只有它的 `count` 更新为 1,另一个纹丝不动:

```
MyApp
 ├── MyButton   count = 1   ← 只有被点的这个变了
 └── MyButton   count = 0
```

原因 05 篇讲过:**state 跟着组件实例走**。`<MyButton/>` 在 JSX 里写两遍,就是两个实例、两格互不相干的账。这不是缺陷——多数时候组件就该各管各的。

## 什么时候需要「共享」

当两处界面要显示**同一份数据**(两个按钮显示同一个计数、两个输入框保持同步、手风琴同时只展开一个面板),把 state 藏在其中一个子组件里就不行了:**谁存谁私有,另一边永远看不到**。

官方原则:**找到这两个组件最近的公共父组件,把 state 放到它那里**——这就是「状态提升」。

## 提升三步(以共享 count 为例)

**第 1 步:删掉子组件的 state**,让它变成纯收 props 的展示组件:

```jsx
function MyButton({ count, onClick }) {
  return <button onClick={onClick}>点了 {count} 次</button>;
}
```

**第 2 步:把 state 搬进公共父组件**,props 下发数据、回调上报变化:

```jsx
function MyApp() {
  const [count, setCount] = useState(0);
  return (
    <>
      <MyButton count={count} onClick={() => setCount(count + 1)} />
      <MyButton count={count} onClick={() => setCount(count + 1)} />
    </>
  );
}
```

点任何一个按钮 → 调父组件传下来的回调 → 父组件 `setCount` → 父组件重渲染 → 新 `count` 以 props 流向两个子组件,**两个数字一起变**。子组件从此不含 state,数据怎么变全由父组件说了算。

## 为什么 `<button onClick={onClick}>` 里还有一层 onClick

提升后的代码里 `onClick` 出现了两次,很多人在这里看晕:

```jsx
<MyButton count={count} onClick={handleClick} />
//            ↑ ①:这只是个「prop」,恰好取名叫 onClick

function MyButton({ count, onClick }) {
  return <button onClick={onClick}>点了 {count} 次</button>;
  //                  ↑ ②:这才是「事件绑定」,React 真正在这里监听点击
}
```

两处**不是同一个东西**:

- **① `<MyButton onClick={handleClick} />`**:MyButton 是自定义组件,这一行**不会绑定任何事件**。`onClick` 在这里只是个普通 prop,名字恰好叫 "onClick" 而已——和 `count` 一样是传东西,只不过这次传的值是一个函数。
- **② `<button onClick={onClick}>`**:`<button>` 是 React 内置组件,这里的 `onClick` 才是**真正的事件注册**——React 会在按钮的 DOM 元素上监听 click,点击发生时调用收到的那个函数。

所以子组件里这一层是在**「接线」**:把父组件递下来的函数,接到真实 DOM 的点击事件上。完整链路:

```
点击 <button>
 → React 调用 button 上绑定的函数(= props 里的 onClick)
 → 那正是父组件的 handleClick
 → setCount(count + 1) → 父组件重渲染
 → 新 count 流向两个按钮,一起更新
```

三个易错点:

1. **忘了接线,点击就失灵**:如果 MyButton 里写成 `<button>点了 {count} 次</button>`(没把 `onClick` 接到 button 上),点按钮毫无反应——自定义组件上的 `onClick` 只是「寄存」在 props 里的行李,子组件不接过去用,它就永远不生效。
2. **同名是约定,不是语法**:写成 `<MyButton onSmash={handleClick} />` + `<button onClick={onSmash}>` 完全合法。叫 `onClick` 是为了望名知义——「这个 prop 是要接到 click 事件上的回调」。
3. **传函数,不调用**(04 篇):`onClick={onClick}` 不带括号;写成 `onClick={onClick()}` 就变成渲染时当场执行了。

这也正是「受控组件」的含义:子组件自己**没有**处理逻辑,只负责把点击转报给父组件,怎么更新全听父组件的。

## 单向数据流与「受控组件」

提升后,数据只朝一个方向流:**父 →(props)→ 子**;子想改,只能调父传下来的**回调函数**(04 篇:`onClick` 传的是函数,不是执行结果)。

官方给这种关系起了名字:

- 子组件的数据**完全由 props 驱动** → **受控组件(controlled)**
- 子组件自己留一部分 state → 非受控(uncontrolled)

上面的按钮就是受控组件:`count` 的唯一权威版本存在父组件里,子组件只负责「显示 + 上报点击」。

## 常见坑:复制 ≠ 共享

```jsx
// ❌ 想在子组件里把 props 拷一份当自己的 state
function Child({ value }) {
  const [copied] = useState(value); // 只拷到「第一次渲染」那一刻的初值!
}
```

`useState(value)` 的初值**只在首次渲染时被采用**(05 篇);之后父组件的 `value` 再怎么变,`copied` 都不会跟着动——两份数据就此失步。同一份数据被多处渲染时,**只存一处**(公共父组件),其余地方全用 props 派生:单一数据源(single source of truth)。

## 实测验证(2026-09-11,react-val-study/react-sharing-state-demo.html)

四张卡片对照,带时间戳日志实测:

- **📖 独立 state**:重演官方图示——两个 `MyButton` 各自计数,点 A 只有 A 变,对应图中「起初均为 0 / 点第一个只更新第一个」。
- **⬆️ 状态提升**:`count` 提到父组件后,点任意一个按钮,两个数字一起 +1;日志显示「父组件 setCount → 两个按钮一起收到新 props」。
- **🎯 单一数据源**:手风琴——`activeIndex` 存在父组件,点开一个面板另一个自动收起,两块面板共用同一格 state 派生各自的展开状态。
- **🔬 对照(坑)**:两个子组件把 props 初值拷进各自的 state,父组件数据更新后拷贝原地不动、当场失步——复制 state 不可行,必须提升。

## 记忆口诀

> **一份 state 一处存:谁用谁收 props,要改就调回调。**
> 两个组件要同步,别各存一份——提升到最近公共父组件,数据自上而下单向流。
